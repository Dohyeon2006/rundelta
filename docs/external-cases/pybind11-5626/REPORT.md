## 本机条件与结果

本机 Fedora x86_64、GCC 16.2.1；CMake 3.31.2、pybind11/pybind11-global 2.13.6、独立 CPython 3.10.19 与 3.12.10。原文 3.10.12 因缺少 libcrypt.so.1 无法在本机启动，未修改系统库。这不是原 Ubuntu 环境的精确重放。

| 运行 | 条件 | 目标退出 | 结果 |
|---|---|---:|---|
| native310 | 干净 3.10 venv | 0 | 构建、导入成功，返回 42 |
| native312 | 干净 3.12 venv | 0 | 构建、导入成功，返回 42 |
| controlled312 | 3.12 venv + CPATH 指向 3.10 头文件 | 1 | 构建成功，导入时版本不匹配 |
| native312repeat | 移除 CPATH，干净重建 | 0 | 再次成功，返回 42 |

四次都在同一 consumer CWD、同一脚本下从空 build 目录配置/构建/导入。均无解析警告，支持范围内完整、存储 verified。没有 --env 选取已知 CPATH 来向报告提供答案。受控错误来自目标的 ImportError，不能称为 RunDelta 自动根因解释。

## RunDelta 独立观察

| 比较 | 差异条数 | 执行线索 / 关键文件排名 |
|---|---:|---|
| native310 → native312（都成功） | 2158 | 新 3.12 解释器第 3 |
| native310 → controlled312 | 2469 | 新 3.12 解释器第 4 |
| native312 → controlled312 | 975 | 无解释器执行差异；新增 3.10 Python.h 第 **177** |
| native312 → native312repeat（都成功） | **446** | 无执行差异；存在临时路径变化 |

所有比较 diff 返回 1，表达“有已观察差异”，不表达运行失败或已找到根因。跨 venv 的前五命中不能替代同解释器的隔离实验：关键隔离比较的前五被退出状态和临时构建文件占据，没有直接头文件线索。

第 177 条脱敏摘录：

```text
New file access
  ${CASE}/pythons/cpython-3.10.19-linux-x86_64-gnu/include/python3.10/Python.h (openat)
  (not observed) → success
```

事件关联表明，编译子进程 cc1plus 成功打开该文件；正常编译子进程打开 3.12 Python.h。两边成功 Python exec 路径集合均为 venv312/bin/python；配置阶段仍访问过 3.12 头文件，不能说失败运行完全未访问 3.12。

## 推断

增加 CPATH 后失败、移除后恢复，结合实际编译子进程的文件访问，支持本次受控失败与头文件搜索路径污染有关。“编译针对旧版本”不要求“执行旧解释器”。这是对受控实验的推断，不是对原 issue 根因的判定。
