# 采集前登记：三个独立样例

保持 RunDelta 产品代码与排序不变。每例在独立目录先 good、再同条件 repeat，最后只改变以下一个条件后运行 bad；每次使用同一命令/CWD、清理本例生成的构建或安装目录。完整原始 JSON/事件/追踪保存在仓库外，不覆盖历史记录。后续分组脚本不能读取本文件的线索来决定折叠。

| 样例 | 正常操作 | 异常注入 | 预先登记的关键线索 |
|---|---|---|---|
| CMake | 构建本地最小 C++ 可执行程序 | 移走 include/answer.h | 该具体头文件成功访问变为 ENOENT；仅退出码不算定位 |
| Cargo | 构建无外部依赖的本地 Rust 包 | 移走 src/build-input | include_str! 输入文件成功访问变为 ENOENT；不是任意构建缓存探测 |
| pip | 离线安装本地最小纯 Python wheel 到独立 target | wheel 文件权限从可读改为 000 | 同一 wheel 打开从 success 变为 EACCES；若只有不再访问则标部分线索 |

pip 场景需要普通非 root 用户。三个异常均是实际工具错误，不伪造采集数据。预期它们产生可检查的文件结果变化；名次以原始 JSON 的实际顺序计，不保证命中。若未出现，不更换样例或调整预期以变绿。

评估原始差异数、候选视图条目数、关键线索在原始/候选前五的位置，以及是否进入分组、降权或遗漏。每个观察结果保留原索引；折叠仅为独立分析视图，observed_differences、可靠性与产品退出码原样保留。任何未来规则都不以工具名、扩展名或具体项目目录作为噪声判断。
