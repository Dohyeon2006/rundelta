# 候选规则与误隐藏风险

规则只存在于 `view.py`，不调用产品 detail_group 或现有降噪规则，也不读取预登记的异常路径来决定分组。工具名仅是运行样例标签与观察到的执行身份，不是噪声谓词。

## 共同约束

只考虑单侧新增/消失、结果集合恰为 success 的文件访问。双侧结果变化、任何错误、执行路径、工作目录、环境、退出及可靠性变化均不进入组。每条成员的事件必须有成功 `O_CREAT` 且带 `O_EXCL` 或 `O_TRUNC` 的写入意图证据，所有关联访问的执行者和直接父进程在本侧必须属于同一实际实例，执行者身份必须已知。

同组在每一运行内要求同一实际执行者和父实例；跨运行只比较观察到的执行路径身份，不比较 PID。根进程父身份用 `<trace boundary>` 明示超出追踪边界，绝不声称观察到了外部父进程。相同可执行路径不证明同一逻辑任务；本原型也不是精准跨运行进程匹配器。

路径分解使用 `/ . _ -` 分隔，长度至少 4 的字母数字片段仅提出结构槽位，不据此声称随机、临时或无意义。不使用已知扩展名、项目目录、工具路径名单、固定临时根目录或熵阈值删除差异。路径前后相同的其余部分仍属于可展示证据。

所有组均标记等价性未经验证。重叠候选按成员数、规则名、模式确定性选择不相交整组，拒绝剪裁重叠组。每个原索引必须且只能出现在一个单项或组中，组放到最早成员的位置，保留产品原顺序的锚点。没有严重性打分、重要性降权或“无差异”推论。

## R1：两侧重复生成路径族

**规则与证据**：路径只有一个槽位不同，其余结构及操作相同；每侧至少两条路径，同一侧重复出现；两侧槽值集合不相交，逐路径调用次数的排序多重集相同，再满足共同的成功结果、写入意图和同父/执行者条件。不强行匹配某个左槽值到某个右槽值。

**保留摘要**：共同模式及 `{slot}`、两侧路径数、每路径调用次数、操作、success、观察到的写入 flags、执行者/父路径、同侧实例条件、原成员索引和“非内容/任务等价证明”。本次 CMake 两组各为调用次数 [1,2] 的 2→2 路径，Cargo 正常组为 [1,1] 的 2→2 路径；模式见 EVIDENCE.json。出现这些名字是观测结果，不是规则条件。

**详情**：`view.py "$ARTIFACTS" cmake normal --details G1` 返回完整成员 change、全部关联标准化事件、原事件索引、flags、执行者/父身份以及每条 evidence 的相对 trace 文件和起止行号。原 JSON 的证据可能采样，详情从 show 的全部 events 重建，不只展开采样行。完整原始字节仍在私有记录对应 raw 文件中。

**反例与风险**：两个生成的响应文件或配置文件即使由同一程序产生、调用次数相同，也可能携带不同选项，导致不同链接结果；同样的原始行为可产生正确或错误内容。`O_CREAT|O_TRUNC` 可能截断已有文件，并不证明路径新生；`O_EXCL` 成功也不证明随后使用或清理。不允许将组标为“无关噪声”或隐藏路径全集。合成内容反例已执行，不能以测试通过声称安全。

## R2：成对生成目录的相对结构

**规则与证据**：目录前缀只有一个槽位不同，每侧恰有一个具体前缀；至少三个唯一的 `(相对路径, 操作, 次数)` 键跨侧一一对应，满足共同的结果、写入意图及进程条件。只折叠被证实对应的键；未对应键保持单项，摘要显示 `unmatched_eligible_keys`，此数仅统计符合准入条件的键，不是所有子树差异。

**保留摘要**：目录槽位模式、全部匹配相对键及调用次数、匹配键数、未匹配合格键数、写入者/父证据、完整成员索引及未经验证标签。不能宣称整个目录树一致。`--details G<n>` 的恢复机制同 R1，可回到全部成员事件。

**反例与风险**：不同依赖版本的展开目录可能结构相同、结果均成功，却有不同源码内容；自动生成配置同样如此。多个逻辑任务使用同一可执行程序也可能误配。准入条件过严格可能漏掉真实临时路径，放宽到多父进程则放大误配风险。真实六组比较零匹配，不建议产品实现；只有合成结构测试成功不构成有效性证据。

## 必须拒绝或等待证据的规则

| 拟议规则 | 缺失证据 / 反例 | 处理 |
|---|---|---|
| 按工具名、扩展名、具体项目目录、临时根目录判为噪声 | 临时目录内可有真实编译输入；任意扩展名可承载配置 | 拒绝 |
| 随机形状或路径槽位相似即折叠 | 版本号、用户选择的依赖名也可能是槽值 | 拒绝单独使用；结构只提候选 |
| 生成后清理即不重要 | 当前采集未提供足够 unlink/rename 清理链；短命响应文件仍能决定构建 | 不实现；将来须展示创建、使用、清理及进程/对象证据，详情返回完整链，仍不能称无关 |
| 失败访问或 success→失败混进成功组 | 缺依赖、权限错误将被淹没 | 拒绝，保留单项 |
| 相同父可执行路径就认定跨运行同一任务 | 同一个 shell 可运行不同命令；PID 也不可跨运行匹配 | 拒绝该推论，显式未验证身份 |
| 用正常→正常“常见”差异训练并永久忽略 | 高频缓存仍可能真实改变输出 | 拒绝；本次正常对照只用于测量 |
| 将组全部挪到末尾或删除原成员 | 组内可能包含重要的成功访问变化 | 拒绝；保留最早索引锚点与全部可展开事件 |
| 折叠后条数少就认定无差异/完整 | Cargo/pip 的共享状态限制不会因分组消失 | 拒绝，可靠性及产品退出码原样保留 |

## 原型本身的限制

flags 从已有原始行辅助提取，尚非通用的系统调用参数解析器，恶意文件名中出现 flags 文本可能干扰；因此不能直接搬入产品。事件顺序和父执行身份来自当前标准化事件，对 PID 复用、exec 时序、丢失父事件、共享文件系统等不充分。对已标 incomplete 的记录，分组依据也可能不完整，本次仅作可浏览的观察实验。

本次没有任何完整的读写内容等价性、因果影响、生成与清理生命周期证明。结果是谨慎保留的候选分组，不是最终噪声分类器。继续实现前应对真实且有意义的成功路径改变测试误折叠率，而非用现有成功失败样例调门槛。
